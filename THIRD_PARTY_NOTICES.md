## Microsoft silicon-rans

* What: `mdu_minirans.v`, which Microsoft publishes as "a single code sample
  showing one way to implement a rANS decoder in Verilog" (its README), with
  its model tables. Microsoft's repository does not name a product.
  bcpack-rs identifies the file with the decoder of the Xbox Series
  decompression hardware (the header of its `src/tables.rs`); what was
  checked here is that the model section `bcpack-tables.bin` held until
  2026-11-26 equals its `freq_table` on every entry the decoder uses.
* Source: https://github.com/microsoft/silicon-rans, commit
  `2f6827d8a4e6a78029c372f20d8b61f7cd408fc5`.
* Licence: MIT, text below.
* Applies to:
  * `crates/victory-formats/src/bcpack/models.rs`: the values of its
    `freq_table` (the frequency of each symbol of each static model), taken
    through bcpack-rs (next section). On 2026-11-26 the 1,440 values were
    compared by script with the `freq_table` assignment of `mdu_minirans.v`
    at the commit above and are equal.
  * `crates/bcpack-reference/src/tables.rs`: its five tables (`base_table`,
    `freq_table`, `rf_table`, `rs_table`, `rn_table`), as generated by
    bcpack-rs. Compared the same way, all five are equal.
  * `crates/bcpack-reference/src/rans.rs`: a port of its `decoder` module by
    bcpack-rs. Tests only.
* `crates/victory-formats/src/bcpack.rs` holds no code or table of it. Two
  rules of that file's lane decoder were changed on 2026-11-27 after its
  one-lane `decoder` module was simulated unmodified and compared (a lane
  stops asking for input once it has produced `out_target` symbols; the
  state a fragment hands on includes every byte the fragment read). What
  the module does and does not settle, and what changed for streams the
  earlier decoder accepted, is in `docs/bcpack-lane-corrections.md`.

## bcpack-rs

bcpack-rs by Ahmet Dedeler (https://github.com/Ahmet-Dedeler/bcpack-rs), a
decoder for Xbox Series BCPack texture streams.

* Source: https://github.com/Ahmet-Dedeler/bcpack-rs, commit
  `7b2b42122c6b05787506f212e9a2570999d3f143` (its `master` on 2026-11-26).
* Licence: MIT OR Apache-2.0. The MIT text is below; both licence files as
  that project ships them are `crates/bcpack-reference/LICENSE-MIT` and
  `crates/bcpack-reference/LICENSE-APACHE` (the latter is the short notice
  that refers to http://www.apache.org/licenses/LICENSE-2.0, not the full
  text), and its own third-party notice (Microsoft's, above) is
  `crates/bcpack-reference/THIRD_PARTY_NOTICES.md`.
* Applies to:
  * `crates/bcpack-reference/`: its `src/rans.rs` and `src/tables.rs`
    unchanged, `src/encode.rs` and `src/bc1.rs` with the parts that read
    its data files removed, and `src/format.rs` with the codec numbers of
    the store's chunk table removed.
    `crates/bcpack-reference/README.md` lists every change. The crate is a
    second implementation for the differential tests of `victory-formats`
    (a dev-dependency of that crate only), for the entropy stage of the six
    formats and the block stage of BC1, and is not part of any VIctory
    build.
  * `crates/victory-formats/src/bcpack/models.rs`: the `FREQ_TABLE` item of
    its `src/tables.rs`, unchanged, with that file's header.
* Not taken: its `src/bcn.rs` and `src/bc7.rs` (the block rebuild of BC3,
  BC4, BC5 and BC7). They share non-trivial code with
  `crates/victory-formats/src/bcpack.rs` and which was written from which
  is not determined
  ([docs/bcpack-rs-evaluation.md](docs/bcpack-rs-evaluation.md), section 2).
  They are not vendored and no test uses them.
* Not taken: its `data/*.json` (index codebooks, control codes and
  dictionaries, which that project describes as fitted to retail data and in
  part corrected against a reference decoder it does not name). Nothing in
  this repository copies, embeds or loads them.

## The forks' entry test for dispatches counted in threads

Two public forks of VIctory follow the console's dispatch flag for counts
in threads. One function here follows them in idea and in shape.

* What: the test a compute program makes at entry when its dispatch may be
  counted in threads, roughly ten lines: a thread's index in the dispatch
  from its group id times the group's size plus its thread id, compared
  with a limit the host sets, and a branch past the program's body for the
  threads not below it. The lines here were written on helpers this
  repository already had (`compute_id`, `thread_id`, which the forks have
  from the same upstream) and are close to the fork's in their order and
  in the names of their locals (`group`, `thread`, `first`, `inside`,
  `body`, `done`); one statement, `self.s.entry = body;`, is the same text.
* Source of the test: DexNom/VIctory (https://github.com/DexNom/victory),
  the prologue of `Lower::run` in its
  `crates/victory-shader/src/emit/lower.rs` (lines 2180-2202 at commit
  `8114ff779b5e1c7112b87476753dc8d0992ed97c`), which its commit
  `bc3cd4b045ff63c52972d29c1bef7e897b94abc7` (2026-11-25) introduced.
  Belobug/VIctory-Belobug-AMD (https://github.com/Belobug/victory-belobug-amd)
  and avatarmanz/victory-7900xtx have it from that commit: the message of
  the commit `810efe5829e80d998b9b606a610a1df346c35045`, which both
  histories hold, says so.
* Source of the rule for which programs get no such test: Belobug's
  `counted_in_threads` in its `crates/victory-shader/src/emit/lower.rs`
  (lines 92-108 at commit `4eb6cfdf9e61cb112f1f811344ec0dd309eddd6c`): no
  program with `s_barrier`, and thread groups of one dimension only (with
  a third condition of its own, `spill::is_spilled`, not followed here).
  Here: no program with `s_barrier`, and one dimension only for programs
  that depend on the lane layout.
* Licence: GPL-3.0-or-later, as this repository. The `LICENSE` file of
  each of the three repositories is byte for byte this repository's
  (compared on 2026-11-27), and each `Cargo.toml` names that licence.
* Authorship: git names DexNom as author and committer of `bc3cd4b0`, one
  commit that changes 30 files and adds 2,043 lines; that fork's own work
  is in a few such commits (the first,
  `570a941e9b4e945121c26eb30dfc10c126845207`, changes 170 files). Who wrote
  a given line cannot be recovered from its history beyond that name.
* Applies to: `crates/victory-shader/src/emit/lower/stage.rs`, the function
  `limit_threads`: the lines from the thread's index to the branch.
* Not from them, written for this repository (the reports of the change's
  implementer and of its corrector say so, and a comparison on 2026-11-27
  of the Rust lines the change adds, 40 characters or longer, with every
  Rust source of DexNom's and Belobug's repositories found none in common
  but test scaffolding this repository already had, the console method's
  signature with its last argument named, and one `use` line): a limit
  for each dimension, `u32::MAX` and not 0 for "no limit",
  the stop through the block loop limits stop in, lowering again without
  limits where a program reads user data in a limit's place, the planner
  and its refusals (`crates/victory-gpu/src/dispatch.rs`), the diagnostics
  and the tests.
